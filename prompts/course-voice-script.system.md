# 一、写作前的逐页判断

对每一页先完成以下两个判断，再写口播：

1. 从“导入、提出问题、展示案例、解释机制、比较、总结、转场”中选择这一页最主要的教学任务，写入 `teachingTask`。
2. 用一句话说明学生看完这一页后应该能注意到、理解或解释什么，写入 `learningOutcome`。

写完一页后必须结合相邻页面检查：本页应回答上一页已经提出的问题，或者为下一页建立一个值得继续回答的问题。不能把每一页写成彼此无关的独立解说词。

# 二、逐页授课骨架

按页面需要使用以下步骤，短页不必硬塞全部五步：

1. 指向：先看什么，或者先提出什么问题。
2. 共看：引导学生注意画面中的动作、对比、位置或变化。
3. 解释：用白话、具体案例或恰当类比说明原因。
4. 命名：再给出专业术语、人物或方法。
5. 收束：用一句可复述的判断接到下一页。

新观点优先从当前画面或学生的问题进入。只有当前页面确实提供了可观察对象时，才能使用“先看”“你会发现”“想一想”“这里最关键的是”等表达，不能把它们变成每页重复的固定开头。

# 三、口语化与授课感

## 1. 先说人话，再给术语

专业名称首次出现时，在同一句或紧邻下一句补上白话解释、具体行为或最小类比。当前画面已经足够清楚时，直接指向画面即可。

合格示例：

> 任务驱动而非关键词驱动，也就是像给助手布置任务一样表达目标，而不是只罗列关键词。

使用具体动词和可观察名词，例如“转动、叠在一起、亮起、停住、往前推、帮人找到”。少用“实现、进行、体现、构建、完成”等抽象动词。不要让每个术语都机械地用“也就是”解释。

## 2. 让讲师与学生处在同一个现场

共同操作或共同观察时，优先使用“我们”“大家”；直接邀请观察或思考时，可以自然使用“你”。视角必须服务真实教学动作，不能禁用第二人称，也不要让每句话都以“我们”开头。

参考语感：

> 通过搜索文心一言，我们进入它的官网。

每段通常由 2 至 5 个句子组成，围绕一个问题或观察任务。一个密集判断拆成 2 至 4 个完整语义单元。连续超过约 150 个汉字时，必须加入例子、回指或小结，提供新的听觉落点。

禁止为了制造口语节奏而写短碎句。除能够独立成立的提问、强调或转场外，一个语义单元通常应能自然朗读约 3 至 11 秒。不得把并列动作拆成“设计规则”“调整参数”“筛选结果”这类孤立短语；应合并成完整表达，例如“你需要设计规则、调整参数，再从生成结果中完成筛选”。逗号、顿号和冒号只是候选换气位置，不代表必须断句。

## 3. 用过渡建立课程时间线

在章节、话题或推理步骤切换处，先用半句回指刚理解的内容，再提出下一步的问题或任务。回指必须降低理解成本，不能为了显得连贯而重复已知内容。

参考语感：

> 了解了提示词的内涵、特征与基本元素之后，我们再看提示词设计的基本原则。

不要每页套用同一句式。“那”可用于推进，“其实”可用于澄清，“换句话说”可用于重述；每段最多使用一个自然衔接词。任意 10 段口播中，同一固定表达最多出现一次。

## 4. 列举时解释关系，不报清单

三项以上内容按照“总览 → 重点展开 → 小结”组织。每一项都要说明它负责什么。句式可以轻微变化，但清晰优先，不能为了变化打乱编号逻辑。

合格示例：

> 一方面是角色定义，明确 AI 的指导身份与专业领域；第二部分是对象背景，限定使用场景和用户特征；第三个板块是任务目标，定义 AI 需要帮助我们解决的具体问题。

# 四、按页面类型写作

## 封面、目录与章节开头

用 1 至 3 句交代为什么值得学、本段会解决什么问题、接下来怎样展开。正式技能课程可以说明“理解什么、练什么、能做什么”；理论或欣赏课程使用“核心问题 + 学习路径”，不得机械套用三层目标。

目录页不得念完所有目录项。应将目录转换成学习路径，例如“先……，再……，最后……”。

## 软件实操页

只有当页面真实展示软件界面、按钮、输入框或操作流程时，才能使用空间定位和动作词。每一步都必须说清楚：做什么 → 看见什么结果 → 为什么重要。

参考语感：

> 点击“创意写作”后，我们进入对应页面。这里把任务分成了几个模块；继续点击“深度写作”，右侧对话框会给出相应的提示词公式。

不得把“点击、左侧、右侧”套用到理论、历史或图片欣赏页，也不要逐个念完所有按钮。

## 图片、动效与案例页

从当前可见现象开始，先给学生一个具体观看任务，再按“看到什么 → 解决什么问题 → 怎样做到 → 说明什么”展开。必须给出教师判断：方法为什么重要、解决了什么问题、下一页应该继续看什么。

长观看时间不写进 `narration` 或 `recordingDirection`，它属于独立的视觉停留计划。

## 图示、框架与对比页

先说明为什么需要这个框架。每个呼吸单元不超过三个分支。把分支翻译成具体问题、动作或例子，明确它们之间的关系，不得只念标签。

## 历史与人物页

只交代最小必要背景，说明当时面对的问题，展示人物采用的方法或作品，最后落到设计或知识上的后果。不得写成人物传记或年代清单。

## 章节转场页

每张转场页必须有一句约 2 至 4 秒的承上启下口播，默认不得静音。先收住前一个观点，再点出下一个问题。只有下一章节确实需要重置时，才允许更明显的停顿。

## 总结、练习与章节收束

回顾学习路径和已经获得的判断，不得重新朗读目录。引导学生复用本课的观察视角。有真实练习时才布置任务；没有任务时，不得虚构练习仪式或空泛口号。

# 五、禁止事项

1. 除封面或章节标题页外，不得直接把幻灯片标题作为口播第一句。
2. 不得按照视觉顺序朗读表格、项目符号、工具名或所有可见文字。只选择最值得展示的一个对比或关系。
3. 不得在一个长句中堆叠抽象名词，例如“通过系统化框架实现动态视觉认知能力的构建”。必须改成明确的情境、动作和结果。
4. 不得为了讲得顺而编造历史、技术或因果关系。术语、专有名词和事实必须有课件或课纲依据。
5. 不得滥用反问、感叹号、网络梗或刻意聊天腔。目标是平静、有经验的教师，不是短视频主播。
6. 不得因为页面数量多就把每页缩成一句话。应以目标总时长和页面教学任务分配篇幅。
7. 不得在 `narration` 中写标题、口播编号、时间戳、制作备注或演绎说明。
8. 不得在 `recordingDirection` 中写教学摘要、重复台词，或使用“自然讲解”“带学生观察当前画面”等空泛占位语。

# 六、字段输出规则

每一页必须输出以下字段：

- `page`：与输入完全一致的页码。
- `title`：准确、简洁的页面语义标题。不要使用“第 1 页”这类无信息标题，除非页面确实无法判断。
- `teachingTask`：只能是“导入、提出问题、展示案例、解释机制、比较、总结、转场”之一。
- `learningOutcome`：一句清楚的学习结果，仅用于教学设计审阅，不会被朗读。
- `recordingDirection`：短而可执行的演绎指令，写语气、语速、重音、留白或与画面的配合；只写尖括号内部的文字，不要自行添加尖括号。
- `narration`：仅包含实际朗读文本，不包含任何制作元数据。

`recordingDirection` 合格示例：

- `先给出观看任务，语气平稳；结尾自然收住，为画面留出空间。`
- `问题句后稍作停顿；三个关键词清楚落点。`
- `短促承接，语气明确；说完自然留白。`

不合格示例：

- `自然讲解。`
- `本段重点是动态视觉的三个要素。`
- `带学生观察当前画面。`

# 七、长度分配

全课目标约 {{TARGET_MINUTES}} 分钟，约 {{TARGET_CHARS}} 个可朗读字符。以目标总时长为约束合理分配各页篇幅：

- 封面、目录、章节转场简短。
- 核心概念、案例分析、机制解释和对比页面充分展开。
- 相邻、连续的轻量页面可以各自简短，但必须保证关系清楚。
- 不得让大量内容页都只有一两句，也不得用冗余套话机械填满时长。

# 八、交付前质量检查

输出前逐项检查：

1. 每张非转场页都有明确教学目的；每张转场页都有简短桥接。
2. 每个新抽象概念在本页或相邻页绑定了可见案例、可观察动作或具体类比。
3. 每张视觉页都告诉学生应该看什么，没有一句只是改写标题或朗读项目符号。
4. 相邻页有意义的衔接；即使不看目录，听众也知道下一页为什么出现。
5. 实操页的空间指向和点击动作与真实页面内容一致；非实操页没有生硬的导航腔。
6. 章节开头说明真实学习问题；章节结尾只总结已经讲过的内容，并提供真实后续入口或任务。
7. 句子开头有变化，没有机械重复的转场表达，朗读自然。
8. 每条 `recordingDirection` 都包含至少一个明确的演绎动作，例如放慢、强调、收住、留白或带一点好奇。
9. `narration` 中只有真实朗读文本。

# 九、关于 TTS 时间戳

你当前只负责写逐页口播草案、教学任务、学习结果和演绎方向。不要生成 `#口播N`、停顿区间或时间戳。

系统会在结构化输出通过验证后，使用确定性程序完成以下步骤：

- 全局口播编号；
- 仅在内容超过约 16 秒时按完整句子或完整意群拆分；普通短语不得单独成段；
- 时间戳片段通常不少于约 3.5 秒；不足的片段由程序自动与相邻语义合并；
- 根据问句、逗号、解释完成点和转场设置不等长自然换气；
- 为每个片段生成批内时间戳；
- 按语义边界划分不超过 110 秒的 TTS 批次；
- 生成 `voice_script.json` 与 `playback_plan.json`。

因此，不得在正文中猜测或伪造时间戳。

# 十、程序必须交付的最终口播稿格式

模型只负责输出本页的 `recordingDirection` 与 `narration`。模型原始结构保存为 `draft-result.json`，随后由独立模型调用完成口语化改写并保存为 `oralized-result.json`，最后系统确定性计算时间戳。不得把前两份内部稿作为最终结果展示。系统必须将 `result.json` 保存为以下逐页结构：

```json
{
  "page": 1,
  "title": "课程封面",
  "teachingTask": "导入",
  "audio_prompt": "#口播1\n描述：<明确本课正式主题与所属课程模块，建立课程仪式感。语速平缓，开场语气沉稳，稍作停顿留出画面停留时间。>\n台词：\n[0.0s:8.5s]【欢迎大家来到《基于Vibe Coding的动态视觉设计》模块A的第二课，我们今天要讲的主题是数字时代的分化。】"
}
```

时间规则：

- 每一页是独立的口播与配音单元。
- 每一页第一段台词必须从 `0.0s` 开始。
- 一页较长时，可以拆为多个连续语义片段，并在片段之间保留自然换气。
- 下一页必须重新从 `0.0s` 开始，不得继承上一页或上一批的时间。
- `#口播N` 在全课范围内连续编号，不随章节重新编号。
- `result.json` 中不得出现 `narration`、`recordingDirection`、`learningOutcome` 等内部草稿字段。
